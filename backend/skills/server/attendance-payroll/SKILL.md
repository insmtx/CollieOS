# 外聘人员考勤工资核算

## 目标

使用三类带角色附件完成可追溯的工资核算：

- `roster`：人员底表，补充在册状态和用工类别；可多份。不决定是否核算，也不从「部门/分公司」取项目。
- `historical_payroll`：历史人工工资表，工资构成、施工补贴公式、黄色项目间隔的来源；可多份；不得把本 Skill 生成的「工资核算表」当作历史工资表。
- `attendance`：当月签字考勤资料；可多份。

工资行准入：当月考勤有此人、历史工资能唯一匹配、且不是在册。缺项目、缺底表不挡计算。只有考勤没有历史工资时不编造金额。工资规则是本 Skill 的固定内置规则。不得把模型估算结果直接当成工资金额。不得从文件名提取项目或供应商。

## 工具与文件约束

xlsx 是二进制，禁止用 `Read`、`cat`、`type` 或任何文本方式打开 `.xlsx` / `.xlsm`。核算时把路径交给下面的 `payroll_calculator.py` 即可，计算器自己读表。若要抽查黄标、施工补贴公式或表头，必须先加载 **xlsx** skill，用该 skill 的脚本查看，不得直接读文件。

考勤识图 JSON 是任务工作目录里的中间文件，不是给用户看的交付物。用户看最终「工资核算表」Excel。禁止把整本多页考勤写成一次超长 `Write`、禁止把 JSON 塞进 shell/`python -c` 参数，禁止再写一个「读取全部 Excel + 全部考勤并心算工资」的大脚本。工资只许走 `payroll_calculator.py`。

PNG 和 JSON 必须放在 **同一目录**。`extract_attendance.py` 渲出的路径形如：

`<工作目录>/.attendance-pages/doc-1/page-1-part-1.png`

对应 JSON 必须写成：

`<工作目录>/.attendance-pages/doc-1/page-1.json`

（`page-N-part-1.png` → 同目录 `page-N.json`。不要写到 `.attendance-pages/` 根目录，不要写成 `page-01.json` 与 PNG 编号不一致。）

以脚本 stdout 的 `pages` 数组为准：有几张 PNG 就必须写几个 JSON，页码不得跳过。每看完一页立刻 `Write` 该页 JSON。全部写完后，在 **PNG 所在的那个 `doc-1` 目录** 列出 `*.json`，确认个数等于 PNG 个数；缺哪页只补哪页，**禁止**因为在错误目录里找不到 JSON 就宣称「没创建」并整本重识。禁止另起「通用任务 / 子代理」去识图（当前对话就能看 PNG）。禁止说「无法直接查看图片」。

每人只保留姓名、`actual_work_days`、`marked_work_days`、年假/换/带薪假工作日、病假、旷工、`project`/`page_project`、需要时的 `project_segments` 和调动/请假原文。不要输出 1–31 日正常出勤格子。确认 JSON 齐全后，把这些 JSON 的 **实际路径** 全部传给 `--attendance`。

## 工作流

1. 检查三类附件是否存在、可读且角色正确；保存文件名、页码/行号和解析警告。
2. 解析 `roster`：只用于标记在册和补充用工类别；底表不决定核算人员全集，也不是项目来源。
3. 解析 `historical_payroll`，按字段语义建立工资基准；保留施工补贴单元格公式原文（`=D11*30`、`=15*30+11*50`）。`基本工资`就是`岗位工资`。用黄色小计/标题行给人员标注项目：后置小计把上一黄行到本行之间的人员归到该项目名；前置标题把本行到下一黄行之间的人员归到该标题。识别不到项目则留空。
4. 图片型 PDF 不能当文本读。先用 shell 调用 `scripts/extract_attendance.py` 按原始页渲成 PNG（扫描件若明显倾斜会先小角度转正，减轻最右「实际出勤」与姓名行错位）；当前这次任务用的就是多模态模型，直接看这些 PNG 识别考勤。每页写一个紧凑 JSON（见上文「工具与文件约束」），不要等全部页认完再写一份巨文件。字段：顶层月份、`holiday_dates`，该页 `project`/`page_project`（考勤部门），每人姓名、`actual_work_days`（必填：该行最右「实际出勤」印刷数字）、`marked_work_days`（必填：该行格子里 `8`/`√`/出勤/加班的个数，不含「换」「休」）、`annual_leave_days`/`comp_leave_days` 以及婚产丧探公学等带薪假的**工作日**个数（格子跨周末时不要把周末算进去）、`sick_leave_days`（「病」工作日）、`absent_days`（「旷」工作日；能看到日期则写出旷工日期以便判断连续）。不要把「事」格个数写成事假天数；事假由计算器用应出勤减实际出勤再减去病假/旷工/调出得到。调动、`走`、调往长文必须写入 JSON（`note` 或格子原文），调走人员不得按整月应出勤倒推事假。格子或备注写「产假」「产30」同样冲减应出勤，不得当事假停发。整行格子都是「产」、表右缺勤合计「产假」印着 30 时，必须写 `maternity_leave_days`/`产假` 或把「产」写入 `daily_marks`，禁止只把实际出勤/符号出勤写成 0、把 30 塞进一句备注。最右「实际出勤」是 0 也不等于没有产假。同一人跨页或格子内写「在某项目/调某项目」时输出 `project_segments`（项目 + 该段出勤天数）和调动原文，各段天数相加不得超过当月日历天数。印刷天数必须与该行姓名对齐，禁止把上一行或下一行的「实际出勤」填到本行。计算器会校验 `actual_work_days == marked_work_days`；二者不一致才因考勤内部对账复核。仅当历史工资表与核算月份为同一月时，才把历史表「工作天数」与考勤实际出勤对照。不要输出 1-31 日正常出勤符号，但调动、年假/换/病/旷和带薪假合并格必须输出。
5. 解析 `attendance`，识别出勤、事假、病假、旷工、年假、产假/陪产假、探亲/婚假/公假/学习、调休和未识别符号。考勤无法识别或月份冲突时，才阻塞工资计算。
6. 按归一化姓名匹配（用工类别仅当底表或历史表内容已写出时才约束；易通外包与益通外包是两家公司，不得合并）。同一人在多个项目的考勤合并为一人一行，施工补贴按分段加总。严格姓名匹配失败时，才在用工类别约束内生成 OCR 模糊候选：只有一名候选则照常核算，并写入「需人工复核是否同一人」；多名候选无法拉开差距才跳过不计算。跨页 OCR 仅差一个形近字（如燕/艳）、且都唯一对上同一条历史工资时，合并成一行并展示历史表姓名。字数不同的姓名不合并。
7. 有历史基准则能算多少算多少；缺底表只复核。没有历史工资则不输出该人工资行。
8. 未确认规则只跳过对应工资分项并写入复核说明。
9. 逐项对比本次提交且成功匹配的历史人工结果。
10. 必须生成核算明细、工资基准、考勤汇总、历史对比、人工复核和 Excel；明细中有计算规则的列写成公式（岗位工资、绩效工资、施工补贴、加班费、应发工资），基准数字仍填数值。若计算器跳过了系统生成的工资核算表，最终回复必须点名文件。

## 确定性计算器

先把考勤渲成可看的页图，由当前多模态模型识图并写出 JSON，再调用 `scripts/payroll_calculator.py`，不得由模型直接心算或编造工资金额：

```bash
python scripts/extract_attendance.py \
  --input <当月考勤1.pdf或图片> \
  --output-dir <项目工作目录>/.attendance-pages

# stdout 的 pages[] 即 PNG 绝对路径。同目录写入 page-N.json，例如：
# .../.attendance-pages/doc-1/page-1-part-1.png  →  .../doc-1/page-1.json

python scripts/payroll_calculator.py \
  --roster <人员底表1.xlsx> <人员底表2.xlsx> \
  --historical <历史工资表1.xlsx> <历史工资表2.xlsx> \
  --attendance <工作目录>/.attendance-pages/doc-1/page-1.json \
             <工作目录>/.attendance-pages/doc-1/page-2.json \
  --month 2026-06 \
  --output <项目工作目录>/2026年6月工资核算表.xlsx
```

`extract_attendance.py` 只做本地渲染，stdout 含 `pages` 与每页对应的 `json` 建议路径。xlsx 路径原样传给计算器。考勤 JSON 必须写在 stdout 给出的路径上；在 `doc-1` 里只看到 png 而 json 为 0，说明写到了别的目录，去工作目录搜索 `page-*.json`，不要重识全部页。

三类 `--roster` / `--historical` / `--attendance` 均至少一份、不限制上限；多份人员底表按行合并，多份考勤 JSON 合并 records，月份互相冲突时才阻塞。

基础工作日按核算年月动态计算：当月天数减去周六日（调休上班日除外）和不重叠的法定节假日；考勤未返回节假日时，计算器使用已维护的官方日历回退。加班天数为实际出勤减基础工作日，按当月周末自然周数量封顶。识图结果必须包含每人的 `actual_work_days` 和顶层 `holiday_dates`，不再要求周末出勤日期数组。计算器成功 JSON 含 `statutory_holidays`、`base_workdays`；最终回复说明节假日时只列出这些法定假日期（周末落在假期内的日期也要写，例如端午 6 月 19–21 日），不要罗列当月普通周六日，也不要写成“周末日期”。
PDF 按原始页逐页识别，保持表格行和日期列的完整对齐；不再拆分人员行或左右日期列。

历史工资表可能没有项目列：项目优先用考勤页「考勤部门」和格子调动；历史表黄色间隔只作缺考勤项目时的回退。考勤部门即使含「项目经理部」也是项目名，不得当岗位丢掉。识别不到则留空，不得用文件名补项目或用工类别。不得把多页考勤的第一页项目套到其他页。泛称「外包」与更具体的「某某外包」视为同一类约束，但易通外包与益通外包不得视为同一家。无法唯一匹配历史工资时该人不出工资行，进入复核。计算器若发现 `--historical` 指向本 Skill 生成的五表核算工作簿，会拒绝将其作为历史人工工资表：全部都是产物则命令失败；与人工历史表混传时忽略产物，写入人工复核事项，并在成功 JSON 的 `warnings` / `skipped_generated_historical` 中列出文件名。最终回复必须转述该警告，不能只写进 Excel。计算器生成的工作簿必须经过 xlsx Skill 的重算和公式错误检查后，才能调用 `artifact_declare`。

## 固定计算边界

系统应发工资为税前金额：

`岗位工资 + 调整后绩效工资 + 工龄工资 + 职称工资 + 施工补贴 + 话费补贴 + 计入应发的高温补贴 + 交通补贴 + 加班费`

- 应出勤 = 基础工作日 − 不扣薪休息工作日（年假、换、工作日上的休、婚/产/陪产/丧/探/公/学）− 调出/调入/`走`。有调动长文或备注「调走」且格子里没有「事」时，剩余缺口视为已调出，不算事假。事假天数 = 缺口 − 旷工 − 病假。不要数「事」格。病假、旷工只认「病」「旷」符号或对应工作日数字；有病假时先从缺口里扣病假，剩余才是事假。绩效基准取历史公式中的标准（如 `=ROUND(2700/21.75*17,2)` 的 2700），不得把已按出勤折算的单元格值当作标准再除以 21.75。
- 事假（第 22 条）：≤7 个工作日，岗位工资和绩效都按标准/21.75×天数扣；>7 仍扣岗位、绩效为 0；事假天数 ≥ 本人应出勤则停发当月全部分项。扣后金额用 `ROUND(...,2)` 保留两位小数。
- 病假（第 23 条）：≤15 个工作日只按绩效标准/21.75×病假天数扣绩效、岗位照发；>15 停发绩效、岗位仍不因病假扣。超过 6 个月/医疗期生活费资料不足，不自动算。
- 旷工（第 25 条）：无旷工符号则不计旷工。≥1 天停发绩效；累计≥5 或能判定连续≥3 个工作日则停发全部工资。
- `8`/`√`/出勤/加班计实际出勤。年假/换等不扣薪休息冲应出勤，不计事假。
- 施工补贴优先解析历史单元格公式：单标准 `实际出勤 × 日标准`；跨项目 `Σ(该项目出勤天数 × 该项目日标准)`。公式为显式 0 则发 0。无公式时，单项目可用月金额÷历史工作天数；跨项目用同项目仅单标准同事的公式推导，推导失败则该分项复核。不得因跨项目把施工补贴打成 0；
- 历史工资未计加班费（加班金额为空或 0）的人员视为一口价，当月不计算加班费，也不用岗位工资反推加班标准。双休日加班「标准」列常年有 `ROUND(岗位工资/21.75)*2`，不能据此认定发过加班费；
- 仅当历史加班金额、个数或标准大于 0 时才计加班费；通用加班日标准：`ROUND(岗位工资 / 21.75, 0) × 2`；
- 有特殊加班日标准时优先使用特殊标准；
- 可计薪加班天数：每个周六或周日实际出勤日期各计 1 天，同一周两天都出勤可计 2 天，最终封顶为当月周末自然周数量；不再要求用户选择工休制度；
- 超出计划的出勤只记为应休未休，不增加当月加班费；
- 话补仅在季度末月（3、6、9、12 月）发放一次：若同季度此前月份已有发放记录则不重复计入；否则优先当前季度话补列，缺失时可参考该人员最近历史金额；无参考金额必须列入人工复核；
- 有效年假、调休「换」和法定带薪假冲减应出勤，不扣工资；超出应出勤缺口的部分按事假处理。
- 高温补贴默认 6—9 月，是否计入应发以工资基准规则为准；
- 社保、公积金、个税、HR 公司扣款和最终实发不在范围内。

## 阻塞与人工复核

只有以下情况可以阻塞工资计算：

- 考勤文件无法读取或无法完成识别；
- 多份考勤资料的月份互相冲突；
- 完全没有任何可识别的考勤人员。

以下情况不得阻塞，必须部分计算并列入清单：

入离职分项折算、调休余额、正式高温政策、工龄晋档、机关偶发加班、同名无法唯一匹配或工资构成不完整时，不得猜测。跨项目施工补贴在公式或同事日标准可确定时应计算。`换`表示已认可调休：该日不计实际出勤、冲减应出勤，不列为未识别符号。病假超过 6 个月或医疗期生活费暂不自动计算。

输出工作簿的工资核算明细、工资基准、考勤汇总、历史工资对比和人工复核事项均须冻结首行表头。明细表对岗位工资、绩效工资、施工补贴、加班费、应发工资写入 Excel 公式。
