# 输入资料映射

xlsx / xlsm 必须由本 Skill 的 `payroll_calculator.py` 或 **xlsx** skill 读取，禁止用文本 Read 打开。考勤识图 JSON 按 PDF 页分别写入工作目录，是中间文件；用户交付物是核算 Excel。

## 人员底表

优先读取：姓名、性别、岗位、人员类别、状态。`部门/分公司` 只表示分公司（一分司、直属项目部等），**不得**当作所属项目。匹配按归一化姓名，用工类别仅当底表或历史表内容已写出时才约束。去除姓名空格和末尾括号备注。不得从文件名猜测项目或供应商。更具体的用工类别（如「某某外包」）与泛称「外包」视为兼容；「易通外包」与「益通外包」是两家公司，不得合并。

“在册”人员不进入外聘工资计算，但要进入忽略清单。底表缺失不阻止有历史工资和考勤的人核算。

## 历史工资表

提取姓名、岗位名称、工作天数、基本工资、绩效工资、工龄工资、施工补贴、交通补贴、话费补贴、加班标准/天数/金额、降温费和人工应发工资。表头中的“基本工资”就是工资规则中的“岗位工资”。绩效若为 `ROUND(标准/21.75*出勤)` 或 `标准-标准/21.75*事假`，基准取公式中的标准。`双休日加班`下的“标准/个数/金额”以及单列`双休日加班`是加班字段组。是否计加班费只看「金额」列是否大于 0；「标准」列的 ROUND 公式不算发过加班费，个数和金额都为空或 0 就是一口价。

**项目**：表内若无项目列，从黄色间隔行识别。后置小计（黄底且「小计」或 SUM 引用上方人员）把上一黄行到本行之间的人员归到 A 列项目名；前置黄底标题把本行到下一黄行之间的人员归到该标题。以行间隔为准，不以 SUM 引用范围为准。合计行跳过。识别不到则项目留空，仍可核算。

优先读取施工补贴 Excel 公式结构（`=D11*30`、`=15*30+11*50`），求值只用于核对。合计行、项目小计行和空白模板行不得当作人员工资基准。

固化为工资基准：岗位工资、绩效标准、工龄/职称工资、施工补贴日标准（可多段）、话补、高温补贴、交通补贴、特殊加班日标准。无公式的单项目月金额才按历史工作天数还原日标准。

## 当月考勤

扫描 PDF 或图片通常没有文本层，需要视觉识别。PNG 在 `.attendance-pages/doc-1/page-N-part-1.png`，JSON 写在 **同一目录** `page-N.json`。有几张 PNG 就写几个 JSON，缺页只补缺页，不要因列错目录而整本重识。不要把全书合成一次写入。每页表头「考勤部门」写入该页 `project`/`page_project`（名称里即使有「项目经理部」也是项目）。同一人出现在多页，或格子内写「在某项目…」「调某项目」时输出 `project_segments`。OCR 姓名差一字或前缀多一字时仍按同一人分别写入各页，由计算器按唯一历史工资合并。`实际出勤`取表右印刷数字。不要在 JSON 里展开 1–31 日正常出勤。特殊符号：

- `8`、`√`、出勤、加班：计入实际出勤；
- `年假`、`换`、工作日上的 `休`、婚/产/陪产/丧/探/公/学：不扣薪休息。满月「产」要把格子符号或表右「产假」印刷数写成 `maternity_leave_days`/`产假`/`daily_marks`，不能只写备注；`实际出勤` 抄最右出勤栏（产假行常常是 0），产假 30 在缺勤合计栏；
- `走`、调往/调出/调入长文：本表不再出勤，冲减应出勤，**不得**算事假；
- `事`、`事假`：不必按格计数；事假天数由计算器用应出勤 − 实际出勤，再减去病假、旷工和调出/调入；
- `病`、`病假`：病假工作日，优先占用缺口；
- `旷`、`旷工`：仅此时计旷工；能看到日期则写出，便于连续旷工判断；
- 格子内项目调动长文：记入项目分段，不作为未识别符号。

页脚「实际工作地」只进复核。

## 输出

工资核算明细对应出勤、事假/病假/旷工、岗位工资、绩效工资、施工补贴、加班费、应发工资中有规则的列写入 Excel 公式，其余列填数值。项目可空。缺失基准人员不应阻塞其他可计算人员。
